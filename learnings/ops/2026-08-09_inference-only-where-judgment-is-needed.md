2026-08-09 — Pay for inference only where judgment is needed; everything deterministic is code

Source: Cody Schneider / Greg Isenberg transcript, triaged in `decisions/2026-07-05_tool-triage.md` §Addendum 08-09. His line: *"Why are you paying tokens for things that can be code that is running on super cheap compute? Only use inference when you need it."* His co-founder's sharper version: *"the only agent is a coding agent — everything else is software the coding agent made."*
Pattern: This is the best idea in an otherwise mostly-uncompliant transcript, and it is not a marketing idea — it is a **margin** idea, which lands directly on yourco because **yourco absorbs 100% of the model spend by doctrine** (CLAUDE.md §Token economics). Deterministic work wrapped in an LLM call costs tokens *and* is less reliable than the same work in Python, because it can vary run to run. The OS already practices this without ever having said it: `dashboard/board.py`, the CRM insight layer, `runtime/consistency-check.py`, `playground/check_isolation.py` and the evidence writers are all deterministic code, and the LLM sits only in the loops that genuinely require judgment. **An accident that isn't written down isn't a standard** — and the drift risk runs one way (it is always easier to ask a model than to write the function).
Implication: Standing engineering rule for every agent and every new loop — **before wrapping a step in an LLM call, ask whether the step has a deterministic answer.** If it does (arithmetic, joins, dedupe, thresholds, formatting, file I/O, ordering, diffing), write the function; the model's job is judgment, drafting, and classification under ambiguity, not computation. Kemba/Kimi apply this when scaffolding a client OS — it is also a *client-facing* margin lever, since the same discipline is what lets yourco hold the "client never sees the token bill" promise as engagements scale. This **does not** contradict the token-economics stance ("a high token bill is good news"): that claim is about tokens replacing headcount and delivering outcomes, not about paying inference to do a subtraction. Both hold — spend freely on judgment, never on arithmetic. Candidate for promotion into CLAUDE.md §Token economics or its own decision if the Founder wants it enforced rather than merely practiced (a machine check in `runtime/consistency-check.py` is not obvious here — this one is a review-time judgment).
