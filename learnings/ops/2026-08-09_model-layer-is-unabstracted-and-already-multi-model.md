2026-08-09 — yourco is already multi-model in delivery; the layer is just unabstracted, and the upgrade dividend isn't flowing

Source: the Founder asked whether yourco should use Codex / ChatGPT / Gemini alongside Claude for the OS. Checking the code changed the question.
Pattern: **Two separate questions get conflated.** (a) *What builds the OS* — Claude Code, settled five times over (OpenHands, Replit, Emergent, opencode, Multica, Codex), and the reason is never model quality, it's that a second autonomous coding runtime duplicates the thing yourco must secure, sanction and eval. (b) *What runs inside a delivered client system* — a different question, and the live one.
**The premise "we're Claude-only" is false.** `clients/sample-client/platform/server.py:183` calls **Gemini** (`gemini-2.5-flash-image`) for Design Studio image generation, in the flagship engagement. yourco already routes by task fit — it just does it ad hoc, per file, with no seam.
**And the cost of that is concrete, not theoretical:** `clients/sample-client/prototype/agent.py:31` pins `claude-opus-4-8` as its fallback model — a superseded ID. CLAUDE.md's **model-upgrade dividend** ("every model/tooling improvement flows to the client as a free upgrade; the offering appreciates as AI advances") is the standing answer to "won't this be obsolete in a year?" — but it is only true if models can actually be swapped, and in the one client agent shipped so far the dividend is provably not flowing. A promise the code contradicts is a credibility problem, not a tidiness problem.
Implication: **Kemba/Kimi — put a thin model seam in `yourco-template` before client #2, not a gateway vendor.** One internal interface (`model(task, prompt)`) resolving task → provider/model from config, so a swap is a config edit rather than a grep. It buys three things yourco specifically needs: the upgrade dividend becomes real and demonstrable; **failover** across providers (a single-vendor outage otherwise takes a client's OS down and yourco owns that reliability promise); and **cost routing** — cheap models for mechanical work — which lands directly on margin because **yourco absorbs 100% of token spend**. Pairs with [[2026-08-09_inference-only-where-judgment-is-needed]]: the same discipline one level up — don't pay flagship prices for classification, and don't pay inference at all for arithmetic. **Do NOT** adopt a second coding substrate or an enterprise AI-gateway product; the seam is a wrench, not a workshop (`decisions/2026-06-14_framework-adoption-stance.md`). Sizing: hours in the template, not a project — and it earns its keep at engagement #2, so it is not a reason to delay closing #1. Immediate no-cost fix regardless: unpin the stale `claude-opus-4-8` fallback.
