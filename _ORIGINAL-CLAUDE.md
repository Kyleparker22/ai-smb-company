## The moat
Agent tooling is commoditizing — tooling itself is nobody's moat. YourCo's durable defensible layer is reliability + eval + observability + approval + enterprise integration + executive trust. That's where the margin lives, and it is exactly what no-code operators cannot deliver. **The model-upgrade dividend (2026-07-20):** because yourco owns the stack and sells the outcome, every model/tooling improvement flows to the client as a free upgrade — the offering appreciates as AI advances while any tool a client could buy depreciates; this is the standing answer to "won't this be obsolete in a year?" (canonical wording: `01_company.md` §"The model-upgrade dividend").

**Autonomy-by-default is the standard (2026-06-25).** Every agent — internal *and* client — is governed by the **Autonomy Matrix** (`processes/autonomy-matrix.md`): the default trajectory of every action is **full autonomy**, earned **per-action on eval evidence**, with the human's routine time trending to **zero**. "No human checkpoint" ≠ "no control" — the control migrates off the human onto the reliability layer (eval gate + guardrails + watchdog + rollback + kill switch), which is precisely the layer no-code can't build, so **full-autonomy-done-right is the premium tier, not the dilution of the moat**. The approval gate stays as the **R1 floor** until evidence earns each action up; **day-one full autonomy on high-stakes actions is the moat-killer to avoid**. yourco proves the climb on its **own** OS first (`runtime/autonomy-matrix.md`). Decision: `decisions/2026-06-25_autonomy-by-default-standard.md`.

## How to work in this OS
- Default to actions that strengthen reliability, eval, observability, or executive trust
- Frame everything as outcomes, not features
- Concise, direct responses; minimal formatting
- Every meeting, decision, and customer interaction should land in this workspace or memory — the OS only compounds if the artifacts compound
- **Change-one-sweep-all (2026-07-06):** canonical facts are duplicated across surfaces (site pages · packets/one-pagers · specs · CRM meta · CLAUDE.md · decisions). When you change one, **grep the repo for the old value and update every surface in the same commit** — a fact changed in one place and left stale elsewhere is the #1 cross-session failure mode (commission %s, tier names, cadences all drifted this way). The machine backstop is `runtime/consistency-check.py` (Mon 07:40 watchdog, reports to `loops/_consistency/`): **when a human catches drift by eye, add it there as a new invariant** so it's never caught by eye twice.
- Closed-loop discipline: every recurring process should have (a) a scheduled task, (b) an artifact output the next run can read, (c) a feedback capture step, and (d) a feed-forward step — patterns written to `learnings/` that the next run reads as its Step 0 and adjusts to. The loop: an agent (often Kolby) observes a pattern → writes a learning → the relevant agents read it next run → behavior adjusts → it gets observed again. (Wired 2026-07-05: every runtime prompt names its Step 0 learnings domain(s), via `runtime/prompts/_loop-contract.md`.)
- Skills discipline: reusable **procedures** (3+ steps a future run would otherwise be re-told) get written as skills in `.claude/skills/` — the how-to complement to `decisions/` (choices) and `learnings/` (observations). Check the library before re-deriving a procedure; write back per `.claude/skills/create-skill/`.
- Runtime box: `ssh user@your-vps` (Tailscale; repo at `~/yourco-os`; cheat-sheet `runtime/phone-access.md`). When handing the Founder commands to run by hand, label every block **[Mac]** or **[VPS]** and name the exact file for any key/env edit — the relay is the #1 historical time sink (session-friction audit 2026-07-05).
- Local surfaces are served ONLY via the server names in `.claude/launch.json` (or `./show.sh`) — read it before `preview_start`, never guess a name; a new demo gets a launch.json entry and a verified-responding URL before the link is shared. Procedure: `.claude/skills/show-surface/`.
- **the Founder sends; agents draft.** Anything going to a human outside yourco — text, email, Slack DM, a link to a client — is produced as copy + link and handed to the Founder. Never send it.
- Git sync model: two machines push to main (this Mac + the VPS runtime), each a separate clone; always pull `--rebase` before push; `loops/` artifacts are runtime-owned (prefer the runtime's copy on conflict); never `git reset --hard`. **Within a machine, multiple sessions/loops share one clone** — to commit your own work use `runtime/commit-scoped.sh "msg" <paths>` (stages only those paths, under the repo lock), **never bare `git add -A`**: that sweeps other concurrent sessions' in-progress files into your commit and buries them. `processes/git-sync.sh` is the full-backup safety net only (it does add `-A`); the runtime loops + git-sync take the shared lock (`runtime/repo-lock.sh`) so they can't race each other's index.
- Secrets never get pasted into chat (transcripts persist on disk) — they go straight into the gitignored env file per `.claude/skills/wire-credentialed-connector/`; a secret that hits chat gets rotated.
