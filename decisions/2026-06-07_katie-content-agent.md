# 2026-06-07 — Content loop handed from Atlas to Katie

## Decision
Build **Katie** as YourCo's Content/Marketing Agent and hand her ownership of the content loop (`processes/loops/content.md`) and its artifacts. Atlas stays the observability layer and reads content output for the Monday briefing; it no longer owns the loop.

## Context
The content cadence loop ran under Atlas. With the roster defined and the handoff pattern proven by Charles (finance), content is the next clean handoff: the SOP and style guide already exist, so building Katie is formalizing ownership + a content-specific eval (voice, moat-anchoring, distinctiveness). Content is YourCo's primary growth lever while pipeline is thin, so giving it a dedicated owner matters.

## Options considered
- **Leave content under Atlas** — bloats Atlas, blurs observe-vs-own. Rejected.
- **Build Katie now (chosen)** — named owner; Atlas reverts to reader.

## Why
- **Keeps Atlas observability-only** (consistent with `2026-06-07_agent-operating-model.md`).
- **Proven low-risk handoff pattern** (same as Charles); read + draft only, publish stays gated to the Founder.
- **Dedicated owner for the top growth lever** — content compounds; it deserves focused eval (voice + distinctiveness) Atlas wasn't holding it to.

## Boundaries set
- **Katie = editorial/written**; Reed = video/demo; Pickle = designed collateral.
- **Katie vs Reilly:** Katie = 1:many public content; Reilly = 1:1 outbound. Katie may mine Reilly's sales artifacts for hooks.
- **Drafts only.** External publishing (LinkedIn/X/newsletter/blog) is human-must-approve.

## Reversibility
Fully reversible — ownership reverts by reverting the SOP header. No external tools were committed; publishing connector is a deferred v1 step.
