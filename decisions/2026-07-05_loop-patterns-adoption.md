# 2026-07-05 — Loop-patterns adoption (from the "15 AI loops" review)

**Decision:** the Founder reviewed Matt van Horn's compilation of 15 community AI-loop patterns (x.com/mvanhorn/status/2068426104088748331) against the runtime. Most are coding loops; yourco's runtime already runs stronger business-ops equivalents (approval gate > prompt-level HITL; watchdog + API-independent alarm > anti-spin demos; inbox-triage IS the 15k-email pattern). Four things were worth taking, all adopted today:

1. **Open-loops chaser** (from #11, human-in-the-loop *queue with reminders and deadlines*) — new weekday-daily loop, Jim, 07:40 ET. Every pending human action becomes a queue item with an honest age; waiting-on-the Founder is nagged daily, parked-by-decision is inventoried Mondays. Direct response to the 2026-07-04 audit (top gaps commercial follow-through — Sample Client aging silently). `processes/loops/open-loops-chaser.md` + `runtime/prompts/open-loops-chaser.md` + systemd pair. **Host step pending: install + enable the timer.**
2. **Streak rule** (from #13, "one green run is luck, a streak is reliability") — the Autonomy Matrix's advancement criterion is now mechanical: N consecutive clean evals with real uses; any incident resets to zero; empty runs don't count. Defaults: R2→R3 = 4 clean weeks · ≥10 uses; R1→R2 external = 8 clean weeks · ≥20 uses. Kolby keeps a Streak ledger in `runtime/autonomy-matrix.md` (counts only — rung changes stay the Founder's), updated each Sunday eval-review. Ledger opened at zero (prior clean runs predate tracking — start honest, not reconstructed).
3. **Loop contract** (from #7/#9/#15 — goal contract, anti-spin stops, completion contract) — `runtime/prompts/_loop-contract.md`, referenced by a footer in every runtime prompt (all 18): fix the done-state before working; stop on no-progress (no third identical attempt), flip-flop, missing input, or budget; "done" requires evidence; an honest partial beats a confident fake.
4. **Client error sweep** (from #12, production error triage) — per-live-engagement nightly loop, **activation-gated, not scheduled** (no live client = empty runs). SOP: `processes/loops/client-error-sweep.md`; trigger registered in `runtime/activation-triggers.md` (§Loop triggers, fires with Kortney's go-live event). Starts R1 (findings + proposed fixes only); auto-remediation is earned per the streak rule. First candidate: Sample Product once public.

**Rejected (and why):** the coding-loop patterns (#1 build-test-fix, #3 harness template, #4 repo maintainer, #5 bounded PGVF, #6 roborev, #10 overnight PR watcher, #14 Clodex) — yourco's runtime is an ops OS, not a continuously-developed codebase; those patterns get used ad hoc in Cowork build sessions, not installed as 24/7 timers. Installing them as standing infrastructure would be machinery for machinery's sake, against closed-loop discipline (every loop must earn its artifact-upkeep cost).

**Revisit:** if a client build (Sample Client, Conduit) becomes a long-running codebase with CI, the build-test-fix + PR-watcher patterns become engagement-level loops there — same activation-gated logic as the error sweep.
