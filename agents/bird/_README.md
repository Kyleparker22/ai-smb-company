## The expansion playbook (generalized — any vertical/type)
1. **Trigger:** Kortney signals an account has held **green** for a sustained window (the desired outcome is landing).
2. **Spot the adjacent role** — the *next* repetitive, human-required job eating the client's time. Sources, all type-agnostic:
   - The **26 employee shapes** (`clients/_yourco-template/employee-patterns.md`) — the menu of roles to map onto this client.
   - What the client *mentioned* in discovery + weekly readouts (`clients/<client>/`) — adjacent jobs they named but didn't buy yet.
   - Kortney's health reads — where the current employee hands off to a still-manual step.
3. **Build the case** — tie the proposed employee to a concrete outcome (hours saved, revenue captured, an outcome they already trust the first employee for).
4. **Quote** — build fee + retainer step-up, **Polo's locked numbers only** (`pricing/`).
5. **Draft the expansion proposal** for the Founder → on approval, hand the signed scope to **Kimi** (who runs the same 48h build loop for employee #2).
6. **Renewals** — flag upcoming renewals early; prep the retention conversation (anchored on outcomes delivered, surfaced from Kortney's trend).

The motion is identical across verticals and employee types — only the *specific next role* (from the shapes menu) and the *outcome framing* change per account.
