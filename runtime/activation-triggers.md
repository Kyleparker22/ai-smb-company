# Activation triggers — the dormant agents and what fires them

> **Status: LIVE REFERENCE** — the 6 trigger-gated agents and what fires each. Not a runbook; nothing here is 'done'.

> The 6 trigger-gated agents (Janice, Kimi, Kortney, Bird, Harry, Kori) are **built activation-ready, not running** — they fire on a real-world event, not a clock. This is the runbook: the machine-checkable condition for each, how the OS detects it, and the host step to turn the agent on. **Detection is automated** (the daily watchdog); **enabling an agent is always the Founder's call.** Owner: Kemba (platform) + Rafi (sanctioning). Created 2026-06-25 (`decisions/2026-06-25_agent-roster-deep-build.md`).

## Why event-triggered, not scheduled
Running these on a timer today = empty runs (no signed client, no invoice, no hire) → wasted tokens, eval noise, and an idle agent inventing work — the opposite of the reliability moat, and against the "prove the unit before adding" rule. So they stay off until their input exists. The OS *watches* for that input and flags it; the Founder activates.

## How detection works (automated)
The **daily watchdog** (`runtime/prompts/watchdog.md`, 08:15 ET) now checks these conditions each run and, if one is met, **leads its Slack post** with `🟢 ACTIVATION TRIGGER MET: <agent> — <condition>`. That's the notify half — it never activates an agent.

## How activation works (the Founder's steps when a trigger fires)
1. **Summon it** — message the agent in its `#yourco-<agent>` channel (the Phase-2 listener), or run it once headless. Channels are pre-provisioned (`runtime/slack-channels.md`); the runtime bot must be **invited** to the channel first.
2. **If it needs a cadence** (Kimi weekly-iteration, Harry AR) — Kemba drafts the loop prompt + systemd timer, **Rafi sanctions it in `runtime/agent-registry.json`**, Kolby evals, then you enable it on the VPS (`systemctl enable --now yourco-<x>.timer`).
3. **Flip identities** where a shared loop hands off (e.g. customer-health "— Atlas" → "— Kortney").

Nothing here auto-runs — every activation step is a human / Kemba / Rafi action, by design. That's the moat, not friction.
