# Per-posting personalization checklist — The Applicant (frontier #11)

> **STAGED — internal until launch (OtherVenture) + this offering's own trigger** (board-ToS/disclosure protocol reviewed by Ray). This checklist governs dry-runs now and real submissions later; no item is skippable in either mode.

Run top to bottom for every posting. Any NO before item 10 kills the application; nothing "proceeds with caveats."

## Gate checks (before any drafting)

1. [ ] **Board row reviewed.** The posting's board has a row in `tos-registry.md` marked REVIEWED by Ray. Unreviewed or prohibited = stop. No creative readings, no "this probably falls under."
2. [ ] **Launch state.** launch-gate clear and gate #3 (CAN-SPAM) closed? If not, this run is a staged dry-run: the kit may be rendered, nothing leaves the building.
3. [ ] **Not a repeat.** Not a duplicate application, not a re-application to a posting that declined us, not a second posting from the same owner already in flight.

## Fit (the honesty gate)

4. [ ] **JD-to-ledger map drafted.** Every JD requirement mapped to an evidenced workflow or explicitly marked "no record."
5. [ ] **Fit threshold met, erring high.** The ledger honestly answers the core of the role. A posting the ledger can't answer is skipped, not stretched (SPEC §3). When in doubt, skip.
6. [ ] **Gaps written into both documents.** The résumé's "what I don't do" section and the letter's mapping both state every gap in plain words.

## Kit assembly

7. [ ] **Every number row-cited.** Each quantitative claim in résumé and letter carries its ledger record id(s). Spot-check three at random against the JSONL.
8. [ ] **Provenance label present** (demo-tenant, until client ledgers exist) — in the résumé header and the letter body, not fine print.
9. [ ] **Disclosure placement verified in the board's actual format.** Render a preview as the board will display it. Line one of the letter and the résumé header must survive the board's truncation/reordering. If not, the board fails for this play even if its ToS row passed.
10. [ ] **Salary line captured internally** — logged to the CRM lead record as pain-budget context for Polo. Confirm it appears nowhere in the outgoing kit.
11. [ ] **Voice pass.** Read the letter aloud against `brand/writing-rules.md`. No slop vocabulary, no "cheaper than a human" framing in any wording, no internal agent names (function titles only).

## Review and send

12. [ ] **Kolby eval pass** on the rendered kit (external claim surface, standard credibility gate).
13. [ ] **the Founder reviews this application individually** — the full rendered kit, not a summary. Approve or kill; no batch approval exists.
14. [ ] **the Founder sends it himself.** House rule, and a permanent R1 floor (SPEC §8): this action class never climbs the autonomy matrix.

## After the send

15. [ ] **CRM row created** — company + deal, channel-tagged `applicant`, posting link + salary signal attached.
16. [ ] **Cost logged** to the channel line (the Founder-review minutes + tokens), per SPEC §6.
17. [ ] **Callback path armed.** Any phone response routes to the disclosed #2 interview line or to the Founder — never to anything that answers as a person.
